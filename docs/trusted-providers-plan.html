Nuncio — Trusted / Untrusted LLM Providers + Correlation Improvement Plan

Status: PLAN — do not implement until approved   Scope: provider registry + trust-aware data plane (P0–P2) + review-driven fixes (Q1–Q5) + structured output (S-track) + correlation/enrichment track (C1–C6). Public-repo safe: no deployment secrets, hostnames, or internal identifiers.

Evidence base: 10-day corpus review (226 alerts: 169 enriched / 57 raw — 47 queue-shed in two bursts; knowledge garnish on 170/170 enriched incl. 59/59 ok/info; avg 7,072 prompt tokens in → 144 out) plus render-path and redaction-path code verification. Corpus findings are folded in as Q-track (§5) and S-track (§6).

Locked decisions (operator-confirmed):
  1. Trusted = skip ALL redaction (precise boundary in §0.4). A provider flagged trusted receives the full relevant alert + context with no secret-pattern, entropy-backstop, or scrub pass applied on the private-plane leg.
  2. Keys env-only. Provider API keys are never stored in settings-overrides.json, never edited via the settings UI, never returned by any GET endpoint. Registry stores api_key_ref (an environment variable name); the process resolves the value from its own environment at boot.
  3. FULL relevant data for trusted. Trusted private-plane calls receive the complete relevant surface (§2): all allowlisted alert extras at full caps, full gathered bundle sections at the active depth budget, triage notes (full depth), and correlated/history/recurrence lines — unredacted.

0. Current architecture (ground truth)

0.1 Provider model

There is no provider registry. nuncio/llm.py speaks to any OpenAI-compatible POST {base}/chat/completions; the model field is an opaque alias. Three hard-coded planes exist in nuncio/config.py _SCHEMA: private (NUNCIO_LLM_URL/KEY/MODEL/…), knowledge (NUNCIO_KNOWLEDGE_*, inherits private when empty), assist (NUNCIO_ASSIST_* with DATA_POSTURE=generic|scrubbed-real + CONFIRM_EXTERNAL_OK double-gate). Wire targets (URL/key/headers/posture/confirm) are NEVER-keys: env-only, read-only + lock icon in UI, POST /settings rejects them. Only the model alias and shaping knobs are UI_EDITABLE. GET /settings.json and GET /config.json are unauthenticated with secrets masked to set/unset.

0.2 LLM call layers

Single transport LLMClient.enrich() (nuncio/llm.py:115). All private calls funnel through Engine._call_bounded (nuncio/engine.py:1149: deadline-clamped socket timeout, circuit breaker on retryable 5xx/429/transport only, abandonment accounting). Layers:

  • Standard single call (_enrich): low depth + degraded-full. 30s budget, 10s per-attempt.
  • Full triage (call 1/2): 15s, log/metric-free, store-only correlated/history/recurrence, plain text, never fails the alert.
  • Deep RCA (call 2/2): 45s, full bundle + triage notes + up to 3 correlations, structured-JSON ladder with capability fallback + one retry.
  • Knowledge garnish (_garnish_with_knowledge): generic classification-table string only, never alert text; skipped as redundant at full depth on a shared endpoint/model; deliberately bypasses the breaker.
  • Assist (nuncio/assist.py): post-delivery worker, own 60s budget, ScrubbedPayload-gated (isinstance enforced), fail → deliver without insight.

0.3 Redaction + correlation baseline

Redaction is always-on and destructive: ingest redacts raw_text before persist/queue (nuncio/server.py:253), so the store, bundle audit, and dashboard only ever see redacted text. Pre-LLM per-field + per-section redact, post-LLM echo redact, knowledge double-scrub, assist 5-stage scrub. Correlation is deterministic: fingerprint (sha1(source|host|signature)[:16]) + causal gate (fingerprint | same service | same strict-unit | declared dependency), host grouping-only, 600s window, flap suppression available. Enrichment sections: recent logs, container state, metrics, kernel, correlated, history, recurrence — assembled by nuncio/bundle.py in fixed order with least-important-first truncation.

0.4 Threat model — trust ≠ injection safety (adversarial-review finding #1)

"Skip ALL redaction" means precisely: skip the secret-pattern catalog, the entropy backstop, and the plane-scrub passes on the private leg. It never means skipping anything in §3.3. Three risk classes, three separate mechanisms:

  • Secret/credential leakage (OWASP LLM02:2025 class) — handled by redaction + scrubs + NEVER-keys + masked GETs. The trusted tier narrows rather than removes this: raw stays inside an operator-designated boundary (local process → trusted endpoint → operator-owned delivery channel) and never at rest.
  • Analysis manipulation via crafted content (OWASP LLM01:2025) — trust level is irrelevant here. Alert text and log lines are attacker-influenceable on either tier. Defenses, all trust-independent: segregated + neutralized external content (BUNDLE sentinels, forged-sentinel stripping), a constrained output contract (JSON schema + deterministic validation and post-LLM gates), and least privilege in the strong sense — the model holds no tools, credentials, or actuators; its output is advisory text consumed by a human reader, and no auto-remediation path exists anywhere in the pipeline. OWASP notes no fool-proof injection prevention exists; the architecture answers with layering plus human-in-the-loop by construction. Accepted residual: a crafted line can nudge the wording of an advisory push message; it cannot trigger action, reconfigure anything, or reach another system. S-track shrinks even this (identity/severity composed in code, not prose).
  • Exfiltration to hosted endpoints — handled by the knowledge/assist skip-by-default for trusted alerts, explicit per-plane trust, and a startup warning when a trusted provider points at a non-private address (P1 §3.1).

1. P0 — Provider registry + providers pane (no behavior change)

Goal: introduce the provider concept, the configuration surface, the UI pane, and per-plane selectors — with zero change to what any LLM receives. All seeded providers behave exactly as today (fully redacted). P0 is the safe merge point.

1.1 Schema

{
  "<id>": {
    "base_url": "http://your-llm-gateway:11434/v1",
    "model": "your-model-alias",
    "timeout_s": 10.0,
    "headers": {},
    "api_key_ref": "SOME_ENV_NAME"
  }
}
  • New _SCHEMA keys in nuncio/config.py: NUNCIO_PROVIDERS_JSON (NEVER, restart-by-env), NUNCIO_LLM_PROVIDER / NUNCIO_KNOWLEDGE_PROVIDER / NUNCIO_ASSIST_PROVIDER (live, UI_EDITABLE, plain strings, not secrets).
  • api_key_ref must match [A-Z0-9_]+. Resolution reads os.environ[ref] from the boot environment only — never from settings-overrides.json, never from a POST body. Fail-closed on typos (adversarial-review finding #2): a ref that is set but unresolvable is a ConfigError when the provider's base_url is non-local (anything outside localhost/127.*/::1/RFC1918, checked with stdlib ipaddress, no new dependency) — a silent downgrade to unauthenticated calls is unacceptable against a hosted endpoint; warn-only when the URL is local. An absent ref stays legal (unauthenticated local-model default, mirroring today's empty-key posture). Precedent for fail-fast wiring validation is the existing ASSIST_ENABLED=true requires ASSIST_URL error.
  • Resolved secrets live in memory only (settings.provider_secrets), excluded from as_dict, masked_config_dict, overrides file, and audit logs (key names only).
  • Validation (boot + apply_changes candidate path): JSON parses; registry holds at most 16 providers (ConfigError above that — metric-cardinality bound enforced at config time, not in UI); each entry has a valid base_url; selectors reference existing ids; empty knowledge selector = inherit private (preserves current inheritance + redundancy-skip); ASSIST_ENABLED still requires a resolved assist base_url.

Capability cache stays per-LLMClient instance, and every selector flip rebuilds the client, so a stale response_format rejection can never leak across endpoints (existing ENRICH_FORMAT precedent).
  • Extra headers deliberately do not fall back to the legacy value when a selector is set (as-built correction: headers can carry credentials — silently sending the legacy endpoint's headers to a different endpoint would leak and/or break; an entry states its headers explicitly). Model/timeout fall back safely.
  • Extra headers deliberately do not fall back to the legacy value when a selector is set (they can carry credentials) — an entry states its headers explicitly. Model/timeout fall back safely.

  • Selector swap is live (pointer swap, no thread restart); in-flight alerts are unaffected (mode/depth/deadline are per-alert). Registry JSON itself is env-only → process restart.

1.4 UI

  • New providers group under the enrich stage; selectors stay in their plane groups (llm/knowledge/assist) so existing layout is preserved.
  • Registry row renders locked (lock icon + reason): id, base_url (redacted display), model, api_key_ref name + key-present set/unset — never the secret value. Selectors render as dropdowns populated from fetched provider ids (same upgrade pattern as the existing default-source select).
  • No trusted flag in P0. The registry parser accepts the field's shape but rejects a truthy value at boot ("arrives in P1") — P0 has no dual-track pipeline, so honoring trust is impossible and silently ignoring it would lie. Trust stays env-only in P1 too (no settings-screen toggle — see §3.1); the pane surfaces trust state read-only. This keeps P0 behavior-identical.
  • Add GET /providers/{id}/test (admin-token gated): performs a 1-token chat/completions call against that provider with a static ping payload (no alert data) and returns latency + model echo. Used by the pane’s Test button.

1.5 P0 acceptance

  • Fresh boot with legacy env only → identical prompts, identical deliveries, all existing tests pass unmodified.
  • Registry-configured boot → same outputs; selectors switch endpoints live; masked endpoints never expose keys; overrides file contains no secret material.

2. What “FULL relevant data” means (inventory)

With redaction as identity, the private-plane LLM input is exactly the output of the prompt builders over unredacted alert + sections. Concretely:

2.1 Alert block

Base fields (host ≤256, service ≤256, state ≤64, output ≤3072, timestamp ≤256 chars) plus the fixed allowlist extras (caps are truncation, not redaction — they stay): details 6144, perfdata 2048, check_command 256 (head), event 64, ack 512, downtime 64, groups 256, address 128, recurrence 64, value 768, links 512 — tail-kept except check_command. Per source:

  • CheckMK: long output, perfdata, check command, notification type, ack author/comment, downtime flag, group names/tags, host address/alias, recurrence count.
  • Grafana: value string/values, runbook/panel/dashboard links (generator/silence URLs stay excluded).
  • Alertmanager: labels-derived host/service/output only (no value/links extras — see C-track note on parity).
  • OpenObserve: rendered match rows, condition/threshold string, firing query, unit/container hint.
  • Generic: host/service/message/severity key aliases, else pretty-printed JSON body.

Still excluded even for trusted (structural, not redaction): non-allowlisted keys (unit, source, category, unmapped native macros, arbitrary ingest keys), over-cap overflow (with [truncated, N chars] markers), and triage-call exclusion of details/perfdata.

2.2 Context bundle (depth-dependent)

  • Standard: category-selected sections, 16 KB cap. Deep: union of full-profile sections, up to 64 KB.
  • Sections: ranked log lines (100/300 lines, 8/24 KB), container inspect (status/restarts/exit/started + 50/150 tail lines), metrics lines (40/80), kernel head+tail sample (50/150), correlated top 8/12 annotated lines, 24h history top 15, one-line recurrence.
  • Order container_state, recent_logs, metrics, kernel, correlated, history, recurrence; truncation drops least-important first (recurrence survives); log-shaped sections cut old head, keep tail.
  • Triage call (full depth): alert minus details/perfdata + store-only history/correlated/recurrence. RCA call: full bundle + plaintext analyst-notes block.

Selection/ranking signals (error tokens, unit normalization, fingerprint basis, dependency edges, domain-suffix canonicalization) influence which rows survive but are not separately transmitted.

3. P1 — Trust-aware data plane (skip-all-redaction for trusted)

Safety invariant: privacy-stripping is bypassed for trusted private-plane legs only. Injection defenses (sentinel neutralization), framing gates (disposition), structural type gates (ScrubbedPayload), evidence caps/escaping, and config masking all stay on in both tiers.

3.1 Trust flag + resolution

  • Registry entry gains "trusted": false (default). Trust is env-only, restart to change (correction folded from review implementation: the registry is a NEVER structure, and trust redefines the data boundary — a settings-screen toggle would put raw-exfiltration one admin-token POST away; the pane shows trust state read-only via /providers.json, changes are env edits with the startup warning below as witness). Metrics label trust state for greppability.
  • Per-alert classification is captured at ingest only and rides the queue tuple as its final elements (…, raw_full, …, trusted) beside mode/depth (adversarial-review finding #3 — verified: server.py enqueues with the same capture-at-ingest discipline documented for mode/depth). The worker threads them into Engine.process(); the engine never re-resolves trust mid-pipeline, so a live toggle flip cannot re-route an in-flight alert (no TOCTOU). In-flight alerts keep the classification they started with. As-built, process() additionally fails closed at its choke point: trusted without a string raw_full degrades to the fully-untrusted path.
  • Knowledge and assist planes keep their current scrubbed-only contract. A trusted alert skips the knowledge garnish and skips assist deferral (delivers the rich leg immediately) unless that plane's own provider entry is also flagged trusted. Startup warning (adversarial-review finding #4): any provider flagged trusted whose base_url is non-private logs an explicit WARNING naming the provider and stating that raw alert text will leave the network — sending raw to a hosted endpoint is then an acknowledged operator choice, never an accident. Egress-assertion tests stay as the second layer.

3.2 Dual-track pipeline (in-memory unredacted, redacted at rest)

  • Ingest (nuncio/server.py): fork raw_red = redact(raw_text) (persist + queue-compat + all store writes + dashboard reads) and raw_raw (queue tuple extra field + worker stack only). Same split for the alert dict (alert as-ingested vs red_alert) and gather output (sections_raw/bundle_raw vs sections_red/bundle_red).
  • Never persist unredacted: store.persist and set_bundle always receive the redacted variant; stats columns (enrichment, assist_insight) store the re-redacted text even when the delivered copy was raw. Dashboard/store readers therefore cannot leak.
  • Fail closed: load-shed, expiry, restart/orphan sweep, and _deliver_raw all use the stored redacted copy. There is no reconstruction of the raw track. Accepted point of no return (adversarial-review finding #10.1): once an alert is delivered with raw content it lives in the notification channel — there is no clawback. Flipping trust off only affects subsequently ingested alerts. Start with a single trusted provider and soak before widening.
  • Never log unredacted: only {type, count} findings and redaction_count (0 for trusted) reach logs/metrics. No repr of raw structures in exceptions. Input-size truncation direction (truncate-and-drop) is preserved pre-LLM in both tiers.
  • Prompt construction: builders take alert_raw/bundle_raw when trusted, alert_red/bundle_red otherwise. Output echo-redact is bypassed only for the trusted private leg; the delivered detail then intentionally carries secrets over the operator-owned delivery channel (document this).
  • Envelope/evidence: caps, _TRUNCATE_ORDER, html.escape, and --- Raw alert: / --- Evidence: markers are unchanged; only the input variant switches. The evidence appendix for trusted uses raw sections.

3.3 What stays on (explicit non-goals for the bypass)

  • Sentinel neutralization (prompt.py bundle/triage neutralizers), disposition hard gate (ok/info strips cause/checks post-LLM), _EXTRA_FIELD_SPECS allowlist + caps, correlation gating, JSON validation/rendering, ScrubbedPayload type gate (trusted needs a separate method/type, e.g. insight_trusted(raw: str), so the untrusted path cannot hand-roll a bypass — update the assist-gate grep test accordingly), config masking, bypass-mode exclusion from assist.

3.4 P1 acceptance

  • Untrusted alert → byte-identical prompts/deliveries to pre-P1 (golden-prompt diff clean).
  • Trusted alert → prompts contain zero «REDACTED:…» placeholders from the secret catalog/entropy pass; store rows, bundles, dashboard reads, and stats columns remain fully redacted; logs contain no raw identifiers.
  • Trusted alert with a hosted knowledge/assist endpoint configured → garnish skipped, rich leg delivered immediately, no hosted egress of raw text (assert via egress test double).

4. P2 — Hardening, observability, rollout

  • Per-provider breakers + metrics (as-built): Engine.provider_breakers: dict[id, CircuitBreaker] (same cb_* knobs for all — knobs stay plane-global) + provider_id; the funnel resolves the active breaker per call via _active_breaker(), so trips/cooldowns are isolated per endpoint and survive selector flips with no funnel-code duplication. Legacy installs (empty map) behave byte-identically. Render nuncio_llm_breaker_trips_total{provider} / nuncio_llm_breaker_state{provider,state} alongside the legacy unlabelled series, which follows the active breaker so pre-existing rules keep working. The per-call llm_calls_total{provider,plane,outcome} counter was deliberately skipped (breaker + abandoned + failures series already attribute load; dashboard planes.private.calls_24h covers volume).
  • Plane info + dashboard: plane_info gains provider (+ trusted boolean) per plane; dashboard pills render model@provider (+ trust marker) with no URL/key exposure.
  • Audit + confirm: trust toggle requires confirm modal; audit log records who/when/old→new; redaction_count==0 + provider/trusted labels on the alert row make trusted deliveries greppable.
  • Docs: docs/CONFIGURATION.md (registry reference, trust contract, env-only rule, hosted-leg skip policy), .env.example (NUNCIO_PROVIDERS_JSON template), config.example.json untouched (classification/dependencies out of scope).
  • Rollout: deploy P0 → soak (selectors exercised, outputs diffed) → enable P1 with a single trusted local provider → verify store-redacted + prompt-raw split via audit queries → cut planes over one at a time. Rollback is selector flip + (if needed) trust-off; no data migration to undo because raw was never persisted.

5. Review-driven fixes Q1–Q5 (10-day evidence)

Small, independently shippable fixes from the 10-day corpus review. Q1 and Q3 are one-condition changes — ship first. Item 6 from the review (category-aware routing, container resource context, recurrence throttling) maps onto S-track §6.5 and C-track extensions noted in C2/C4, not here.

Q1 — Skip knowledge garnish on ok/info (review item 1)

Evidence: garnish fired on 170/170 enriched alerts, including 59/59 ok/info — every resolution notice ships a problem-framed generic essay. Change: hard gate in _garnish_with_knowledge (nuncio/engine.py:1213): return the enrichment unchanged when disposition(severity) != "problem" — same authority as the existing cause/checks gate (engine.py:1035-1043). No new config key (matches the disposition-gate precedent, not a knob). Tests: ok/info replay → zero General guidance blocks; token-delta accounting on the corpus. Accept: 0 garnished ok/info; problem-leg output byte-identical.

Q2 — Burst resilience for monitor sweeps (review item 2, REDESIGNED after evidence)

Evidence (corrected — the first analysis misread the burst class): the 47 queue-sheds are 26 critical TRIGGERED + 21 ok across ~25 distinct services in two one-minute bursts — a monitor sweep with every service flapping at once, not same-fingerprint info repeats. Same-fingerprint coalescing would have caught ~none of them. Three sub-fixes:

  • Q2a — severity-priority queue. FIFO sheds in arrival order, so criticals drown behind recoveries. The work queue becomes a priority queue (critical 0, warning/unknown 1, info 2, ok 3; FIFO sequence counter within a tier). Criticals always enrich first during bursts; overload still degrades to the existing raw fallback, just in the right order. Queue-full/load-shed semantics unchanged.
  • Q2b — ok-severity cheap path. Recovery notices run full-depth 2-call RCA today whose cause/checks output the disposition gate then discards — pure waste. At ingest, severity == "ok" forces depth = "low" (single call; summary kept). Info keeps global depth.
  • Q2c — cross-service digest for generic info/ok. Grouping key (source, severity) (the burst class is heterogeneous services, not repeats): first notice of a window goes immediately; subsequent arrivals within NUNCIO_DIGEST_WINDOW_S (default 0 = disabled, opt-in — review closure: defaulting ON would silently change delivery semantics for existing untrusted installs), are terminally recorded (delivered_digested) and folded into one enriched digest ("N services recovered" / "N update notices"). Criticals/warnings are never held; failure-marked items bypass. Digest state in-memory only; restart fails open with the first notice immediate (post-restart arrivals start a fresh window — adversarial-review finding #5). The digest's summary now counts and remembers the opening notice too (review closure #11), with bounded key/line caps.

Files: server.py (queue type, put/unpack sites, depth override, digest buffer/sweep/emit, maintenance duty, nuncio_digested_total), store.py (mark_digested CAS → delivered_digested, already covered by purge_delivered's LIKE 'delivered_%'), config.py (NUNCIO_DIGEST_WINDOW_S schema + live key + App plumbing). Tests: priority order under burst; ok→low override; digest burst → 1 immediate + held + 1 digest; critical/warning bypass; restart fail-open; disabled window passthrough. Accept: burst replay enriches criticals first with zero update-attributable sheds; recovery legs cost one call. Ops note: raise NUNCIO_CONCURRENCY above 1 alongside (restart-required, endpoint-load dependent).

Q3 — Treat "-" host as missing in log queries (review item 3)

Evidence: all OpenObserve alerts carry host -/None (template has no host field); one enrichment openly reports insufficient context from unrelated log lines. Verified mechanics: the codebase already treats - as missing everywhere via real_host() (nuncio/model.py:126-133; persist server.py:276, correlation correlate.py:139) — except the O2/Loki query builders, which test truthiness (nuncio/clients/logs.py:153-156), so "-" adds a str_match(field,'-') clause matching nearly every line. Change: guard both builders with real_host(host); unit-only queries then run on the unit clause alone (the structured unit-field clause already exists as recall backup). Keep the adapter emitting - (fingerprint stability) — fix at the query site only. Tests: host - → no host clause in emitted SQL; unit-only recall parity on the corpus; the unrelated-lines case replays clean. Accept: no query ever contains a placeholder literal; ranked-log precision on unit-only alerts improves or holds.

Q4 — Read-only container visibility (review item 4)

Evidence: NUNCIO_CONTAINERS=null, so 122/169 bundles carry an empty Container state (container not found) section and the thinnest alert class (vanished containers, 300–700 byte bundles) bottoms out at generic advice — no exit codes, no tails. Change: deployment-side: front the socket with a filtering proxy (candidate: tecnativa/docker-socket-proxy) and point the containers backend at it. Hard requirement from verification (adversarial-review finding #9): stock CONTAINERS=1 also exposes GET-only filesystem reads (/containers/{id}/archive, /export) and process listings (/top) — a "read-only" proxy without sub-path denies is insufficient. The deployment must add explicit deny rules for archive/export (and top unless needed) ahead of the containers allow, keep POST disabled, and prove POST /containers/create and GET …/archive both 403 in acceptance testing against the pinned proxy version. Nuncio itself only ever calls GET /containers/{name}/json and GET …/logs. No prompt/bundle code changes; the existing (container not found) path is the automatic fallback if the proxy is unreachable. Tests: proxy-down replay → byte-identical output to today; proxy-up replay → populated state sections on the vanished-container class; deny-rule probe suite green. Accept: operator decision recorded (hardened proxy deployed, or explicitly deferred with the thin-context stub from S-track as the honest fallback).

Q5 — Device-name allowlist segments (review item 5)

Evidence: CheckMK device names hit the entropy backstop inside the delivered raw line itself, so push headlines arrive anonymized from the operator too. Change: ops-side, no code: append the actual device-name segments to the settings-only NUNCIO_REDACT_ALLOW_KEYWORDS via POST /settings (segment-anchored, case-sensitive — add exact -/./_-delimited segments, never whole hostnames). Verify by redaction_count delta and raw-headline spot check on the next firing of each affected check. Accept: raw lines name the device; unrelated-secret redaction counts unchanged.

6. Structured output S-track (severity · affected · issue)

Diagnosis (verified in code): the LLM writes the identity today — summary prose feeds the headline crux (envelope.py:99-141), so the "who" is a docker ID, None, a bare IP, or a redacted placeholder, while the deterministic facts sit behind the prose. Cause and checks share one paragraph with the issue, so thin-context alerts read as confident filler, and the 120-char brief-leg cut (delivery/__init__.py:173) can land mid-sentence. Best practice (PD-CEF shape: severity/source/component/class + summary; PagerDuty title/body/runbook guidance) is fields first, prose second — the layout below.

6.1 Format

Push (brief) leg — title keeps <emoji> <entity> — <crux> but entity is engine-composed; body line 1 (inside the 120-char budget) is WARNING · web-app on dock-01 · 13 restarts since 11:54: severity as a word, never emoji-only.

Severity: Warning (firing since 11:54)
Affected: web-app on dock-01 · container
Issue: restarting frequently — 13 restarts vs threshold 1
Likely cause: application crash or config error (exit evidence…)
Next: 1) container logs  2) recent config change  3) host memory pressure
Also: helper-queue crashed concurrently (possible shared cause)
History: 3rd in 48h · Links: runbook · dashboard

--- Raw alert / --- Evidence (unchanged)

ok/info legs render Severity/Affected/Issue + resolution line only — no cause, no checks, no garnish (companion to Q1). A thin-context alert renders an honest stub (Issue … on … — context unavailable) instead of filler.

6.2 Contract + rendering

  • LLM returns {issue, likely_cause, checks[]} — no summary prose, no hostnames. issue required, ≤140 chars; validate_structured (prompt.py:496-551) swaps the summary 10–250ch rule for it. Engine composes Severity/Affected/History/Links deterministically from the alert dict + store, so invented hosts/ports (observed class) cannot reach the identity slots; checks stay advisory.
  • best_display_name() (new, envelope.py): service on host with canonical collapse, skipping -/None/redacted parts via the existing real_host guard; fallback chain (adversarial-review finding #8) when both are absent: source, then source + category, then the literal alert — never an empty string. Composed from the in-memory original; the normal untrusted output-redact pass still applies afterward (an untrusted entity may honestly render as a placeholder, matching today's raw line). Feeds headline, brief line 1, and the Affected row from one place.
  • Garnish repositioned below evidence under its own heading when kept (Q1 already removes it from ok/info) — it stops masquerading as analysis.
  • Migration: dual-contract release behind the existing format switch (legacy default for one release): legacy goldens byte-identical; new contract validated against the stored 10-day corpus (entity == alert dict on every row; brief ≤120 with severity+entity intact; stub shape on thin rows); then flip the default. Email HTML renders the header rows as a table.

6.3 Relation to other tracks

S-track needs P1's input-variant plumbing (raw-variant sections flow into the new renderer) — schedule it after P1 sign-off to avoid contract churn. Review item 6a (intent-aware knowledge routing) is substantially addressed by Q1 instead: update/info classes no longer receive crash guidance at all (garnish skipped off-problem); full intent-keyed routing remains future work. Items 6b/6c extend C2/C4 as noted there.

6.4 As-built deviations (verified green)

  • Brief severity prefix dropped: the title already carries emoji + entity + crux; duplicating a severity word into the 120-char body costs crux budget for no new information. Brief stays title + issue-first-line.
  • Knowledge-garnish repositioning deferred: moving the garnish below evidence would restructure detail assembly for cosmetic ordering; Q1 already removed the harmful cases. Revisit only with evidence of confusion.
  • Entity separator stays /: best_display_name fixes selection (skips -/None/redacted, falls back source → source+category → literal) without churning the established host/service headline shape or downstream parsers.
  • Contract rename is dual, not cutover: issue (10–140ch) preferred, legacy summary (10–250ch) accepted only when issue is absent; the normalized result keeps the summary key so renderers are untouched.

7. Correlation / enrichment track C1–C6

Baseline is deterministic Level-2 (dedup → temporal window → causal gate). Each phase below is independently shippable, keeps the existing gate as the admission authority, and adds rank-only or additive signals first.

C1 — Semantic near-dup (rank-only inside the gate)

Problem: same meaning, different wording (e.g. Grafana vs CheckMK texts) never fingerprints together. Change (as-built): new nuncio/semantic.py (stdlib-only token-Jaccard + bounded operational window + distribution()); hook in correlate.py contributes up to +1.5 inside already-gated rows with a similar wording (NN%) reason. The veto is deliberately narrower than "vetoes grouping": it withholds the bonus only — gate authority is untouched, so a fingerprint-hit with differing services still groups as recurrence; comparisons run normalized-case so capitalization drift never vetoes. Visibility first (adversarial-review finding #6): Jaccard is synonym-blind and order-insensitive, so ship it with nuncio_semantic_pairs_observed_total / _p50 / _p90 / _max on /metrics — the operator watches the distribution to decide whether the embedding upgrade is worth it, and flat recall reads as a metric, not as silent correctness. Files: new nuncio/semantic.py, hook in correlate.py rank path, surfaced as a reason string. Accept: false-grouping rate measured on replay harness stays flat while near-dup recall rises; veto path covered incl. mixed-case service names.

C2 — Change-aware context (highest-yield RCA signal)

Problem: “what changed in the last 15m” is absent from the bundle. Change: new optional changes collector section (recent image updates, config applies, restart bursts from already-available signals) appended to the bundle + a one-line ## Recent changes header; capped like other sections. Files: collectors.py, gatherer.py category wiring, bundle.py order (near correlated, truncates early). Accept: degrades to UNAVAIL with no pipeline impact when no change feed is configured. Extension (review item 6b) redirected on evidence: neither backend exposes container CPU/mem (Prometheus emits host up{} lines, CheckMK host/service state), so bolting the existing metrics section onto container profiles would burn bundle bytes on almost-signal while breaking the single-signal narrowness discipline the test suite pins. Container resource visibility needs backend-aware queries (cAdvisor-style selectors) or the Q4 socket proxy — tracked as a follow-up, not smuggled into C2.

C3 — Learned co-occurrence edges, rank-only (as-built deviation)

Problem: dependency_hints is hand-maintained and rots. Change (as-built): the live-manifest providers from the original plan (compose depends_on, CheckMK parents, network aliases) are all unavailable to a read-only Nuncio (no socket/config tree, CheckMK exposes no parents via the machine-visible API) — so C3 ships a learned edge set instead: new nuncio/topology.py mines near-repeat co-fire from the alert store (warning/critical only, once-per-service-per-day, ≥3 distinct shared days, 30d window + hourly TTL, ≤5 partners/service) into the same {service: [partners]} shape, merged rank-only: the boost (+1.0, "often seen together") applies to already-gated rows only, explicitly directionless (co-occurrence can't say who is upstream), and can never admit, suppress, or fabricate a chain. Static dependency_hints keep sole gate authority. Files: new nuncio/topology.py + store.service_day_rows (bounded), correlate.py (learned param), collectors.py/config.py threading. Accept: canary test proves a bogus learned edge re-ranks but never suppresses the true root (gate untouched).

C4 — Storm mode (rate-derivative response)

Problem: cascades produce hundreds of alerts in seconds; per-alert enrichment wastes budget on symptoms. Change (as-built): an ingest-rate tracker (App, rolling 60s window; tripped at 20+ alerts/min, active for 300s, exposed as nuncio_storm_entered_total / nuncio_storm_active) downgrades non-critical alerts to the cheap single-call path while active — criticals never downgrade and already queue first under Q2a. The adaptive correlation window was dropped as structural over-reach (threading a per-alert window through every collector would blur the gate's determinism for marginal recall); the simplex is the depth lever. Extension (review item 6c) — recurrence-based throttling of non-alternating repeats (the observed 38× class) as periodic digests instead of every repeat — remains future work (flap suppression only triggers on alternating runs; a same-severity repeater is a distinct, delivery-policy change). Accept: burst replay downgrades symptoms to low depth with criticals full; storm metrics ride /metrics; storm clears after its window with behaviour byte-identical to before.

C5 — Past-incident RAG + calibrated confidence

Problem: the model re-derives known fixes from scratch and overstates certainty. Change (as-built): store.past_incidents(fp, limit) (terminal delivered rows only; reads already-redacted enrichment/payload first lines — safe on both trust tiers), rendered as a capped ## Similar past incidents store-only section; the structured contract gains an optional confidence (0–1) key, validated to [0,1] and rendered as Confidence: NN%. when ≥0.5 or Insufficient signal — treat the cause as a hypothesis. below it — attached ONLY when a cause was attributed (never on recovery legs) and never used to suppress anything (annotation, not a gate). Accept: abstention rate rises on thin-signal replays; no raw-text expansion.

C6 — Feedback loop + source parity

Problem: no learning from operator split/merge; Alertmanager parity lags Grafana (no value/links). Change (as-built): a persisted feedback table (dedupe index on key+action+ref) + admin-gated POST /feedback (confirm_root | split | merge; split requires ref_key; unknown keys refused 404) + read-only GET /feedback.json; corrections aggregate into clamped ±1.0 pair bumps (store.feedback_corrections, 180-day window) consulted by rank_correlated's corrections param — rank-only on already-gated rows (operator merge/split reason), loaded through a per-gatherer hourly cache in config. Alertmanager adapter gains value / links extras mirroring Grafana (runbook_url/runbook/wiki, values map fallback). The plan's precision/recall + abstention dashboards remain a follow-up (observed correlation outcomes would need a labelled replay corpus first). Accept: weight drift bounded (±1) and auditable (every bump traceable to a feedback row); Alertmanager/Grafana extra parity under test.

9. Test matrix

  • Config: registry parse/validation (bad JSON, bad URL, bad ref name, unknown selector, assist-without-URL, knowledge-inherit), legacy-seed equivalence, overrides file never contains secret values.
  • Masking: /config.json + /settings.json + startup log show set/unset for keys and registry secrets; selectors plain.
  • Redaction split: canary secrets (key-like, JWT-like, high-entropy) appear verbatim in trusted prompts and delivered detail, but never in store rows, bundles, stats, dashboard payloads, or logs.
  • Egress: hosted knowledge/assist doubles receive zero raw bytes for trusted alerts by default; trusted→trusted legs receive raw.
  • Injection: forged «BUNDLE-START/END» / SEVERITY= / JSON-instruction strings in logs are neutralized in both tiers; disposition gate strips cause/checks on ok/info.
  • Breaker: per-provider trip/cooldown/half-open isolation; selector flip resets capability cache; metrics labels present.
  • Correlation: replay harness (fingerprint stability, gate precision/recall, veto, storm fusion/non-fusion, topology staleness, abstention rate).
  • Load: queue-full + deadline-exceeded paths deliver redacted raw; no raw retention after drain.
  • Q-track: ok/info replay carries zero General guidance blocks with problem-leg output unchanged; burst replay yields 1 digest + 0 queue-sheds with failure bypass and restart fail-open; host - emits no host clause with unit-only recall parity; raw headlines name allowlisted devices with unrelated-secret counts flat.
  • S-track: corpus goldens — entity equals the alert dict on every row (never invented), brief ≤120 chars with severity+entity intact, stub shape on thin rows, legacy/new dual-run clean; forged entity strings neutralized; disposition stub on ok/info.

  • Untrusted golden prompts unchanged; trusted prompts carry full data with zero redaction placeholders; every at-rest/read/log surface stays redacted; hosted legs provably receive no raw bytes by default.

  • Per-provider breaker/metrics/dashboard live; trust changes confirmed + audited; docs updated; single-trusted-provider soak passes with store-redacted/prompt-raw split verified.

  • Each phase ships behind its own flag with replay-harness precision/recall/abstention numbers and a rollback path that restores the deterministic baseline.

Q-track done when

  • ok/info garnish is zero with problem legs unchanged; burst replay yields one digest and zero update-attributable queue-sheds; unit-only recall holds without placeholder clauses; raw headlines name devices; the container-visibility decision (proxy or documented deferral) is recorded.

  • Corpus goldens pass (entity correctness, brief budget, stub shape); legacy/new dual-run is clean; the default flips with no test changes and push output spot-checked on a live alert of each disposition.
